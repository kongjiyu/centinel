# Centinel Project Instructions

Google Drive attachment imports allow up to 100 MiB of original bytes, with metadata/Content-Length/stream bounds and content-page sizing to bound resident downloads. Explicit forced sync resets the provider cursor so previously unsupported unchanged files can be re-evaluated; ordinary incremental sync preserves it. Byte import is separate from PDF text/diagram assessment and deployment Storage limits. See `docs/GOOGLE_DRIVE_100MB_IMPORT_2026-10-28.md` for verification and current limits.

Explicit Source Resume captures owner/project-scoped paused index revisions before clearing the expected owner hold. It conditionally queues those exact revisions, allowing saved-source Reviews with a different source fingerprint to resume without scheduling obsolete identities. Ordinary polling/Review queueing must never infer resume authorization from an already-cleared hold. Concurrent new pauses, transferred owners and live leases remain protected by revision CAS. See `docs/SOURCE_INDEX_RESUME_2026-10-28.md` for regression evidence.

Readiness source fingerprints exclude healthy sync progress while retaining source access, remote revision, exact item/version availability and terminal causes. An unchanged import check at finalization waits within the existing job deadline without repeating completed model work; changed evidence retains queue/defer behavior. Reacquire the current owner session before persistence after that wait. The Readiness card admits one status GET per lifecycle so slower responses cannot be invalidated by every two-second poll. See `docs/READINESS_SYNC_STABILITY_2026-10-28.md` for verification and deployment state.

## Product and Sources of Truth

Centinel is a local-first desktop quality-assurance platform with two product areas:

- **Centinel Static** reviews artifacts and source code, checks requirement traceability, and reports inconsistencies.
- **Centinel Dynamic** drives web applications with Playwright, uses visual reasoning when needed, and captures reproducible evidence.

Use these references in priority order:

1. [`DESIGN.md`](./DESIGN.md) for all user-facing design decisions.
2. [`docs/Centinel_PRD_Revised.md`](./docs/Centinel_PRD_Revised.md) for product scope and requirements.
3. Current feature specifications in `docs/` for authentication, reviews, and project assessment.
4. Existing tests and implemented behavior for current technical contracts. Flag material conflicts with the PRD instead of silently changing behavior.

## Tooling and Commands

This is a pnpm workspace. Use pnpm rather than Bun, npm, or yarn so the checked-in lockfile remains authoritative.

```bash
pnpm install                              # install workspace dependencies
pnpm dev                                  # sidecar, demo server, and Tauri app
pnpm dev:check                            # read-only port/health preflight
pnpm test:dev                             # development launcher checks
pnpm --filter centinel test               # frontend tests
pnpm --filter @centinel/sidecar test       # sidecar tests
pnpm --filter centinel build              # TypeScript + Vite frontend build
pnpm smoke                                # integration smoke checks (requires configured services)
pnpm build                                # production Tauri build
```

Prefer targeted tests while iterating, then run the smallest complete suite that covers the change. Do not claim a check passed unless it was run successfully; report environment or credential blockers explicitly.

The root development launcher reuses healthy listeners, checks Windows process ownership against this checkout, rejects unrelated occupied ports, and cleans up only processes it launched. A Vite listener alone does not mean the desktop window is open: if the workspace Vite server is healthy and this checkout's Tauri executable is not running, the launcher starts the native shell while reusing Vite. Reuse does not reload an older sidecar: restart the original dev terminal after backend changes.

For PowerShell process lifecycle checks, use terminating errors before mutation and verify both command identity and recorded creation time. ConvertFrom-Json may already deserialize an ISO timestamp to DateTime: cast that value directly to DateTimeOffset for UTC comparison instead of parsing its localized string representation. A failed identity check must stop before terminating or restarting any process.

## Frontend and Design

Before changing UI, CSS, branding, icons, animation, responsive behavior, or user-facing layout, read and follow [`DESIGN.md`](./DESIGN.md). It is authoritative even when an older screen has not yet been migrated.

- Migrate complete screens toward the command-center system without changing product behavior unless requested.

For frontend design changes:

1. Run `pnpm --filter centinel build`.
2. Verify at 1440×900, 1200×900, and a narrow viewport.
3. Confirm styles do not leak into unrelated screens.
4. Run relevant frontend tests.
