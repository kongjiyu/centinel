# Grouped Findings and requirement gaps

## User contract

Show one concise issue-type row (for example **Code Deep Nesting Issue**) and list all matching affected occurrences in its details. Insufficient requirement evidence and incomplete/missing requirement mappings remain actionable document findings. Show exactly the available requirement, document, code location, source version and excerpt supporting each occurrence. Unavailable relationships are explicit; do not invent code links for a missing requirement.

The user's later clarification requires a table-only index and a separate continuous document when opened. **Race Condition Risk** can group multiple affected flows, and one occurrence can reference several interacting code segments. Review outcomes belong to Security, Personnel, Technical or Business; Readiness independently supplies document quality gaps such as inconsistency, unclear content and missing documentation. Review evidence/requirement-coverage warnings are scope limitations within that workflow, not a fifth AI assessment domain. Existing Dynamic Testing evidence remains supported separately.

## Implementation specification

1. Group by explicit stable issue type, deterministic rule ID, evidence-gap code, or exact title within the same source and origin. Unknown-title fallbacks retain their domain boundary; never group all security/business concerns merely because they share a category. Deep nesting aliases resolve to `cq-deep-nesting`; explicit Race Condition titles support legacy data. A specific issue type may retain several domain impacts and detector origins. Readiness never merges into Review. Original titles/descriptions remain in occurrence details.
2. Grouping is a UI projection in both shared Findings presentations. Preserve occurrence IDs, statuses, findings counts, original history, risk inputs and exports. Show matching occurrence counts and highest ordered risk/severity. Mixed states are visible; a group has no bulk Resolve/Dismiss action. Filters select occurrences before grouping; search still finds original titles, evidence and paths. Cross-view finding-ID links select the correct occurrence/group/page.
3. Project/Review use a full-width table and open a full-width detail document, with no empty sidebar. All matching occurrences render in continuous anchored sections with their own description, public causal steps when recorded, source references, recommendation and actions/history. Identical saved recommendations appear once overall; differing recommendations remain per item. Code previews load only on explicit action through the Review-owned frozen-version reader and reject reference-version mismatch. Readiness retains all saved references. Unknown historical flows/relationships remain explicit; no new AI calls synthesize missing history. The legacy unused-by-production default renderer remains compatible.
4. For each scoped requirement whose frozen mapping state is Incomplete or Missing, create a warning evidence gap containing requirement identity and available source/mapping references for any Review type. This is a coverage/evidence finding, not proof the implementation violates the requirement. Existing readiness findings continue to describe insufficient requirement content. Project Findings additionally exposes the latest Review's saved document gaps with honest load failures.
5. Additive JSON/type metadata only; no schema migration, model calls, deletion, retrospective finding rewrite or risk recalculation. The installation AI hold remains unchanged.

6. Model requests may return `domain`, stable `issueType`, bounded public `logicFlow` steps and `relatedLocations`. Shape validation rejects malformed metadata. Every secondary path, line, artifact/version and exact source excerpt is validated against frozen sources before persistence; invented secondary evidence is dropped and makes the assessment partial/failed. Only valid references reach existing `findings.location` JSON. This validates provenance, not the semantic truth of a claimed race condition.

## Acceptance

Test multiple nesting locations grouped once; unrelated rules/domains separate; mixed severity/status and per-occurrence actions; filter/search/deep-link pagination; all saved readiness references; requirement gaps for code and traceability Reviews; safe frozen previews and unavailable evidence. Run relevant suites, frontend build, sidecar type check; verify scoped styles at 1440×900, 1200×900 and narrow width using synthetic fixtures. Record results and limitations after implementation.
