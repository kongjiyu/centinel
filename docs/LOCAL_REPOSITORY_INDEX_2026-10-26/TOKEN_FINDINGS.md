## Requirements for an exact contract catalog

This is a separate proposed policy, not an implemented or accepted shortcut:

1. Inventory every frozen document section with exact version/hash/range, including examples, defaults, exceptions, qualifiers and negative requirements. Distinguish source documentation from confirmed requirement authority.
2. Retain exact quoted contract passages and provenance. Derived labels and summaries are navigation aids, not replacement evidence. Unresolved sections and coverage gaps must remain visible.
3. Select code-related contracts using exact identifiers, source dependency relationships and local index retrieval. A lexical or semantic score alone cannot prove an omitted contract irrelevant.
4. Fall back to whole document context when relevance or completeness is uncertain. Keep independent full-source/document sweeps and every required domain assessment.
5. Evaluate contract recall separately, including deliberately low lexical overlap, exceptions, cross-file behavior, contradictions and negative controls. Accept narrowing only after completed same-scope quality evaluation with no lost gold or unsupported absence claims.

## Reading the usage report

Freezing, indexing, deterministic checks, model analysis and persistence are separate stages. Logical phases distinguish initial analysis, domain/citation/response repair, semantic support and support repair. Physical file reads and exact AI-supplied files are different inventories. Repeated appearances are not additional unique files.

Use actual reported tokens for consumption. Character counts are prompt-size diagnostics; admission estimates are pacing controls. Cache-read tokens are already included in input. Unknown failed/in-progress usage is not zero. A partial execution cannot establish a full-review token reduction, precision, recall or quality acceptance.
