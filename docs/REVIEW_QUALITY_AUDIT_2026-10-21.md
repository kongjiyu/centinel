## Blocking findings

1. **P1 — Invalid model output can resolve existing issues.** `sidecar/src/review/orchestrator.ts:713–740`; `findings.ts:129–136`; `projectCorrelation.ts:61–74`. A changed-source review returning `{message:"I could not complete the review"}` normalizes to zero findings and is marked `succeeded`. The production orchestrator/in-memory repository probe first recorded an ownership issue, then returned this malformed result under comparable scope/configuration. The second review ended `pending_approval`, reported zero findings and one resolved issue, while its analysis map remained `unverified`; the correlation included resolution eligibility. Validate the response schema and distinguish incomplete assessment from an actual empty result. Invalid/incomplete analysis must not establish resolution or reduce current risk.

2. **P1 — Unsupported model claims retain ordinary finding severity/risk.** `sidecar/src/review/locationValidation.ts:21–33`; `findings.ts:92–125`; `orchestrator.ts:761–764`. A Critical claim at nonexistent `missing.ts:999` had its location stripped but was still saved as Critical. A real file/line with nonexistent quoted evidence counted as a verified location. A title-only response became a Medium finding with empty evidence. These were executable offline probes against the production orchestrator. Require minimum finding fields and source-anchored evidence; retain unsupported observations as explicitly unverified candidates outside ordinary current-risk totals. File existence/line bounds alone do not validate a claimed defect. PRD STA-03/STA-05 require attributable evidence and distinguish suspicions from findings.

3. **P1 — Traceability read failures do not block approval.** `centinel/src/screens/ReviewActivityScreen.tsx:269–278,390`. A rejected traceability request is converted to `status:'unavailable'`; `canDecide` checks findings failure but has no traceability read-failure state. A technically successful review therefore still offers Approve after this evidence request fails. `docs/REVIEW_WORKFLOW_APPROVAL_EVIDENCE_SPEC_2026-09-10.md:101` explicitly distinguishes contract-level unavailability from a failed request and requires the latter to block decisions until Retry succeeds. Track these states separately and provide an evidence retry action. Verified by code tracing, not a live approval action.

4. **P1 — Historical Review sources show mutable project inventory.** `centinel/src/screens/ReviewActivityScreen.tsx:1014`. The sources section mounts the project `ArtifactsPanel`, while the reviewed count comes from the frozen manifest. After importing B or updating/removing reviewed A, the historical Review shows current files/content and project Add/remove controls. Render immutable reviewed versions and scope; expose project source management as a separate navigation action. This violates the persisted-input/session-immutability contract in `docs/PROJECT_ASSESSMENT_REVIEW_OVERVIEW_SPEC_2026-09-12.md` and PRD STA-07. Verified by source tracing; no live data was modified.

5. **P1 — Traceability snapshots reuse stale mappings outside review scope.** `sidecar/src/review/supabaseRepository.ts:556–573`. Snapshot creation rereads all current requirements and classifies existing mapping status strings without consulting this Review's scope or frozen artifact versions. An offline repository probe with a selected requirement mapped as complete to a deleted file saved that requirement as Complete and also included an unselected requirement as Missing. The method consulted only snapshot/requirements/mappings tables. Freeze and scope requirement/mapping inputs, verify mapped artifacts/versions, and distinguish mapping existence from assessment of current implementation. PRD STA-04/STA-07 require honest traceability and frozen context.

## Recovery and presentation findings

1. **P1 — Retry cannot incorporate repaired sources.** `centinel/src/screens/ReviewActivityScreen.tsx:539`; `sidecar/src/review/orchestrator.ts:298–307,512–524`. The summary tells blocked users to address the evidence issue and retry, but the UI always sends `refreshSourceManifest:false`. The service reloads the old frozen artifact set, so newly imported/repaired evidence is excluded. Offer explicit saved-source versus updated-source retry paths; preserve saved-source retry for transient provider failures. Verified by code tracing.

2. **P2 — Grounding sanitation discards valid feature/path/domain links.** `sidecar/src/review/orchestrator.ts:950–960`. Lines 718–720 validate `sourceLocator.analysis`; sanitation immediately replaces the entire locator with standard/requirement provenance or null. Root executed the actual method with a valid-shaped analysis locator: before was the analysis object, after was null. Feature finding-navigation links therefore disappear before persistence. Preserve independently validated analysis and requirement/standard provenance; cover the complete persistence pipeline in regression checks.

3. **P2 — Export inventory contradicts current reconciled findings.** `sidecar/src/report/snapshot.ts:154–175`; `sidecar/src/report/supabaseSnapshot.ts:getProjectAssessment`; `sidecar/src/report/markdown.ts:127`. Risk uses the current reconciled projection, but inventory takes raw historical finding rows and says every item has its current state. An offline report probe retained two historical occurrences as New while current risk contained no items. Label the historical inventory explicitly and add a reconciled current-issue inventory; preserve immutable per-review evidence.

4. **P2 — Older human activity can select the wrong latest Review in exports.** `sidecar/src/report/snapshot.ts:64–67,178`. Terminal reviews are ranked by `updatedAt`. An older approved review created October 1 and updated October 21 displaced a newer review executed October 20 in an offline report probe. Rank latest execution by execution boundaries/creation order and present later human decisions separately. The new review's evidence should not disappear because someone acts on an older review.

5. **P2 — Retained readiness verdicts are not visibly identified as stale.** `centinel/src/components/ProjectReadinessCard.tsx:114–142`; `centinel/src/readinessFindings.ts:15`. The card renders prior Completed/Missing labels while updated-source work is queued/running, ignores `stale`, and explains previous results only after an error. Findings simultaneously hides stale gaps. Label previous assessment/date and updated-source assessment status consistently without dropping the retained snapshot. Verified by code tracing.
