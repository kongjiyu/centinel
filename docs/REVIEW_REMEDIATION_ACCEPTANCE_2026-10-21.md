## Implementation decisions

1. `review/assessmentValidation.ts` owns the versioned structural/evidence checks. Invalid JSON does not automatically retry/fallback during Static Review. Invalid or explicitly unverified code assessments end as Failed/partial with a saved limitation and safe partial findings. A source-code map with no recognized features cannot produce clean completion. No real model ran during implementation.
2. Resolution uses version 2 eligibility plus `static-assessment-2026-10-21.1` and an exact assessed source-reference basis. Unverified source regions, missing proof, potential gaps and unresolved local edges cannot resolve old issues. Current projection refuses old v1 absence-based proof, conservatively reopening derived presentation where necessary; persisted finding decisions and historical snapshots are unchanged.
3. Traceability v2 context uses additive fields inside the existing snapshot summary JSON: frozen grounding, inclusion basis and version provenance. Public summary/API/export responses whitelist counts and retain record-level evidence status; frozen grounding bodies are not copied into harness metadata. New executions no longer use mutable completion-time traceability queries. Saved retries reuse context; refresh captures a new context.
4. The authenticated Review-owned `source-artifacts/:artifactId/content` reader verifies project, manifest membership, saved version ownership and actual downloaded hash. It does not depend on a current artifact row. Backend frozen-source execution/indexing also reads the exact authorized version after current artifact removal. Existing source management remains in Project Source.
5. Exports add optional `currentFindings` without repurposing historical `findings`. New generator version is `project-report-v4`. Latest Static Review attempt keeps terminal failures visible and does not borrow an older success's evidence. Readiness and decision evidence presentation use explicit stale/loading/failure states.

## Limits and operational handoff

Live AI remains paused. No secrets/configuration were changed, no live approval/finding decision was made, and no data migration/reset, commit, push or external publish occurred. Report, traceability and validation fields are additive; no database schema migration is required. Retained snapshots and human decisions remain historical evidence.

The full Dynamic Testing backend suite was not rerun during this remediation. Its audit baseline contains Windows/process/symlink/browser failures; this work does not establish a green whole-product backend. Native Tauri, live Supabase storage lifecycle and real-model calibration still require separate acceptance. Existing missing mapping version proof is displayed honestly, not inferred from current files.
