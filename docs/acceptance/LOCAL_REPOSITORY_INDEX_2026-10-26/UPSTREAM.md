# Upstream integration research

**Checked:** 26 October 2026. **Upstream:** `open-codebase-index` 0.38.1, npm `latest` for both `open-codebase-index` and its legacy alias `opencode-codebase-index`. The registry metadata reports Node `>=22.13.0`; the published package declares Windows x64 and ARM64 native targets. The v0.38.1 release/tag is the latest published version found. [npm registry: preferred package](https://registry.npmjs.org/open-codebase-index/latest), [npm registry: legacy alias](https://registry.npmjs.org/opencode-codebase-index/latest), [upstream v0.38.1 package metadata](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/package.json), [release](https://github.com/Helweg/open-codebase-index/releases/tag/v0.38.1)

This research used read-only public package/source metadata. No repository source or provider credential was uploaded, and no paid provider request was made. The exact upstream package and MCP SDK were later installed in the Centinel workspace by the parent implementation task for local adapter work.

## Public integration surface

Use the published MCP server as a child process, over stdio. The preferred binary is `open-codebase-index-mcp`; `opencode-codebase-index-mcp` is retained as an alias. It accepts `--host codex`, `--project <absolute-path>`, and `--config <absolute-path>`. The package root export is the host plugin object, not a documented reusable indexer/snapshot API, so Centinel should integrate through the public MCP protocol instead of importing internal storage code. [Installation guide](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/docs/installation.md), [CLI argument parser](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/adapters/mcp/cli-options.ts), [package exports and binaries](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/package.json), [root plugin export](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/index.ts)

The MCP surface includes `index_status`, `index_codebase`, `codebase_context`, `codebase_search`, `codebase_peek`, `implementation_lookup`, `call_graph`, `call_graph_path`, and other retrieval/diagnostic tools. `codebase_context` can return `structuredContent` when called with `diagnostic: true`; `codebase_search` returns formatted text. `index_codebase` supports explicit force/dry-run controls, so Centinel can keep indexing an explicit builder action and use `index_status` as the read gate before search. `call_graph` returns structured symbol-resolution metadata but v0.38.1 does not include the edges in `structuredContent`; its formatted text is the only public edge result. The thin adapter parses only the bounded resolved edge locations from that public text and marks them as partial structural context. In a Windows MCP fixture, `codebase_context` structured locations were absolute paths, so the adapter accepts only paths inside its staging root and converts them back to relative source paths before returning them. [MCP tool names](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/tools/tool-names.ts), [MCP schemas and handlers](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/adapters/mcp/register-tools.ts), [MCP execution result shapes](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/tools/execute-common.ts), [graph formatter](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/tools/utils.ts)

Recommended spawn shape:

```text
open-codebase-index-mcp --host codex --project <staging-root> --config <private-runtime-config>
```

The MCP process uses stdio by default. Its `--config` is an explicit JSON file; it must remain local and must not be put in the shared snapshot. [MCP CLI](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/cli.ts), [configuration loading](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/adapters/mcp/cli-options.ts)

## Storage, snapshot and portability

For Codex, `scope: "project"` stores configuration at `.codebase-index/config.json` and the index under `.codebase-index/index/`. The global index uses a home-directory path and is unsuitable for a per-project shared snapshot. Project-scope file paths are stored relative to the project root in the current path-storage format; older project indexes containing absolute paths require a force rebuild before they are portable. The indexer checks path-storage version, embedding model, dimensions, and embedding-strategy version. A provider-name mismatch is only warned about, so Centinel's manifest must also validate provider protocol and its own compatibility fields. [Configuration paths and legacy path warning](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/docs/configuration.md), [path storage and compatibility checks](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/indexer/index.ts)

Upstream's documented local index consists of SQLite metadata/chunks, usearch vector artifacts, BM25 artifacts, and index/file-state metadata. SQLite retains indexed chunk text and source text; the vector index has companion metadata that binds it to the same publication. The project does not document an index snapshot export/import command or Supabase/cloud backend. **Inference, exercised locally:** a compatible snapshot can be restored without SQL rewriting by extracting the complete, closed project index directory into the expected `.codebase-index/index/` location under a fresh staging root, then letting the pinned public MCP server open it. A real Windows run with a fake loopback embedding provider succeeded after copying the index to a new absolute root, omitting SQLite's shared-memory file, retaining the non-empty `codebase.db-wal`, and reading the restored index through public `index_status`, `codebase_context`, and `call_graph`. The small fixture inventory was `codebase.db`, `codebase.db-wal`, `file-hashes.json`, `inverted-index.json`, `vectors`, and `vectors.meta.json`; this describes an observed 0.38.1 index, not a format guarantee. Emit a recursive filename inventory with each snapshot because upstream publishes no stable import/export API. Package version and MCP compatibility remain required before retrieval. [Architecture and local artifacts](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/ARCHITECTURE.md), [SQLite chunk schema](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/native/src/db.rs), [vector publication binding](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/native/src/store.rs), [public CLI commands](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/adapters/cbi.ts)

Snapshot creation must wait for `index_codebase` to finish and the child to close before copying. Upstream publishes several files (SQLite, vector, BM25, branch/file state) separately and does not claim one atomic transaction across them. Copying a live index could therefore produce an internally mismatched bundle. Include the complete closed index data tree; do not edit SQLite. The Windows fixture leaves a non-empty `codebase.db-wal` after the child closes; it carries committed database changes required by the restored MCP server and must be included. Omit `codebase.db-shm`, transient lock/runtime directories, and configuration; the next MCP process recreates its own shared-memory state. Preserve the staged source tree for local freshness checks and path resolution, or materialize the same frozen source files locally before status/search. The snapshot contents include recoverable code excerpts, paths, symbols, graph edges, embeddings, and optional blame metadata; treat the bundle as source code and store it under the existing project-member authorization. Exclude `.git`, runtime config, API keys, `.env`, logs, and any unselected files by constructing the staging tree from the frozen manifest rather than copying a checkout. [Upstream publication boundary](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/ARCHITECTURE.md), [SQLite chunk fields](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/native/src/db.rs), [default file protections](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/docs/configuration.md)

Minimum Centinel compatibility manifest:

| Field | Required value or check |
| --- | --- |
| Upstream package | Exact package identity and version (`open-codebase-index@0.38.1`) |
| Runtime | Supported Node version and native platform; Windows x64 is declared |
| Host/scope | `codex` / `project`; restore under `.codebase-index/index/` |
| Frozen source set | Stable ordered relative paths, content hashes, file count, and manifest hash |
| Embedding | Provider protocol, exact model ID, dimensions, strategy version; never credential or owner ID |
| Index data | Bundle digest and complete-file inventory; accept only after `index_status` confirms compatibility and freshness |
| Graph results | Exact engine version and parser version; keep at most 10 resolved edges per symbol and validate each path/line against the frozen manifest |

On a missing or incompatible snapshot, report that state and stop before `codebase_context`/`codebase_search` or `index_codebase`. Search creates a query embedding; reindexing creates document embeddings. Both can incur provider usage. A deliberate builder flow can index the frozen stage once, close the child, and publish the completed bundle. Do not let ordinary GET/search paths trigger automatic indexing, stale-snapshot rebuilds, provider retries, or fallback.

## Voyage provider compatibility

There is no native Voyage provider in v0.38.1. Upstream's `custom` provider posts to `<baseUrl>/embeddings` with `{model, input}` and expects OpenAI-style `data[].embedding` plus optional `usage.total_tokens`; it validates vector count and the configured dimensions. It does not send Voyage `output_dimension`, `output_dtype`, `input_type`, or `truncation`. [Custom provider request/response code](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/embeddings/providers/custom.ts), [custom provider configuration](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/docs/configuration.md#custom-openai-compatible-endpoint)

Voyage 4 Lite/4/4 Large accept `output_dimension` 1024 and return float vectors by default; the API's default truncation is enabled. Voyage recommends `input_type: "document"` for indexed text and `input_type: "query"` for searches. Embeddings made without `input_type` are documented as compatible with those made using it, but are not task-prefixed for retrieval. [Voyage embeddings API](https://docs.voyageai.com/reference/embeddings-api), [Voyage model dimensions and retrieval guidance](https://docs.voyageai.com/docs/embeddings)

The saved Voyage setting can be adapted to upstream's custom contract by configuring `dimensions: 1024`, the exact Voyage model, and a local custom OpenAI-compatible endpoint. A loopback proxy is the smallest Centinel adapter: accept upstream's custom request, use the saved owner-scoped Voyage configuration in sidecar, send one native Voyage request with explicit dimension/float/no-truncation, and return OpenAI-shaped vectors/usage. Do not put the Voyage key in the MCP config or child environment. The upstream provider interface itself does not carry query/document intent through `embedBatch(texts)`. Centinel preserves that intent without patching upstream by using two sequential MCP sessions against the same compatible project index: a builder session points at a loopback proxy route fixed to Voyage `input_type: "document"`; after it exits, a retrieval session points at a different route fixed to `input_type: "query"`. Both use the same model, 1024 dimensions and index strategy. The proxy remains the only component with the saved Voyage key and records usage. Disable upstream retry/fallback, auto-index and file watching so a session cannot issue hidden calls or race the other session. [Upstream provider interface](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/embeddings/provider-types.ts), [Voyage API](https://docs.voyageai.com/reference/embeddings-api)

The upstream default embedding retry count is 3; HTTP 429 is retryable in the custom provider. Disable retries and fallback for this integration (`indexing.retries: 0`, `embeddingFallback: false`) and disable background/automatic index work (`autoIndex: false`, `watchFiles: false`). Provider-capacity errors must become a terminal result in Centinel's proxy and stop the current operation. [Upstream retry defaults](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/docs/configuration.md#L257-L280), [429 handling](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/embeddings/providers/custom.ts)

## Centinel adapter contract

Launch the pinned public `open-codebase-index-mcp --host codex --project <staging-root> --config <private-config> --mcp-idle-timeout 0` entry point through MCP stdio. Timeout `0` selects the direct MCP worker path instead of the CLI's idle-supervisor child. The adapter sends explicit calls only: `index_codebase {}`, `index_status {}`, `codebase_context {query, limit: 12, tokenBudget, diagnostic: true}`, and bounded `call_graph {name, direction, filePath?}`. It does not invoke history, knowledge-base, network-search, cleanup, or automatic setup tools. [CLI timeout/worker selection](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/cli.ts), [public MCP handlers](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/src/adapters/mcp/register-tools.ts)

Build the MCP config in a private temporary directory with only the loopback proxy URL and per-session loopback capability token. Give the child an isolated temporary `HOME`/`USERPROFILE` and application-data paths so inherited global configs, embedding defaults, knowledge bases, repository history, and unrelated settings cannot change the frozen scope. Set `include` to the staged frozen file paths, `exclude` to `.git/**` and `.codebase-index/**`, and the exact staged paths in `indexing.includeIgnored` and `indexing.includeExcluded`. Set `scope: "project"`, `indexing.autoIndex: false`, `watchFiles: false`, `retries: 0`, `autoGc: false`, `gitBlame.enabled: false`, `embeddingFallback: false`, `reranker.enabled: false`, and diagnostics/effectiveness metrics off. The config is deleted only after the MCP child is confirmed exited. [Include/exclude behavior](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/docs/configuration.md#L334-L350), [MCP runtime state](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/docs/configuration.md#L321-L333)

Use sequential sessions for embedding tasks: the index-building session sends only to the loopback route that maps requests to Voyage `input_type: "document"`; the query session sends only to the route mapped to `input_type: "query"`. Both set the same saved Voyage model and dimensions. The sidecar proxy is the only component that reads the Voyage key, validates vectors/usage, and applies capacity limits. Check `index_status` before accepting any restored index. After a public `call_graph` response, parse only exact `[resolved]` edge rows, reject out-of-root locations, cap to 10 edges per symbol, and stamp `open-codebase-index@0.38.1` plus parser identifier `public-call-graph-text-v1` in provenance; unresolved edges and malformed lines produce no evidence. The public tool's structured graph content currently lacks edge locations, so this small text parser is version-pinned and its results remain supplemental, partial static context. The public context tool's structured result carries exact source ranges but may use absolute paths; convert only after proving the path is inside the staging root.

Close the MCP session before `portableIndexFiles(<staging-root>/.codebase-index/index)` enumerates the recursive inventory. Reject symlinks, unsupported entries, rollback journals, live lock directories, oversized file sets, and snapshots above the configured limits. Include the closed `codebase.db-wal`; exclude the transient `codebase.db-shm`, runtime metadata, config and lock files. Store the ordered relative filenames and hashes in the snapshot receipt. A Windows fake-provider integration test verifies fresh-root restore, status, structured vector retrieval, resolved graph locations and separate document/query proxy routes without using a paid embedding call.

## Graph scope and limits

Upstream provides parsed symbols, call edges and paths through `call_graph` and `call_graph_path`, along with code communities and PR impact tools. It uses static parsing and conservative resolution; its supported local import/export and call patterns vary by language. Dynamic, ambiguous, external, and runtime behavior remain unresolved. Use graph results as retrieval context only, not as proof of complete program flow or security. [Architecture](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/ARCHITECTURE.md), [graph tool contracts and limitations](https://github.com/Helweg/open-codebase-index/blob/v0.38.1/docs/tools.md)

## Integration decision

| Question | Finding | Centinel contract |
| --- | --- | --- |
| Latest release? | 0.38.1 on both npm identities; Node >=22.13; Windows x64 native target | Pin 0.38.1; use supported Node and package binary |
| Public CLI/MCP? | MCP stdio binary, explicit project/config/host args; public search/index/graph tools | Launch one isolated child for a manifest staging root; use MCP calls only |
| Supabase snapshot backend? | None found; index remains local files | Centinel owns private Storage bundle, provenance manifest, member checks, cache and download |
| Portable snapshot? | New project paths are relative; no public import/export format | Copy/restore the complete closed directory; validate via pinned `index_status`; do not rewrite SQLite |
| Voyage native support? | Not built in; generic custom OpenAI-compatible protocol omits task/input parameters | Separate document-builder and query-retrieval proxy routes preserve Voyage task type; only the sidecar proxy holds the saved key |
| Graph? | Static partial call graph, not whole-program flow proof; v0.38.1 structured response omits edge rows | Parse at most 10 resolved lines from public `call_graph` text, label the source/version, and validate each location against the frozen manifest |

The remaining blockers are product-owned: durable snapshot upload/download and compatibility metadata, source-bundle privacy/access policy, deletion/retention behavior, and exact tests for restored 0.38.1 indexes on Windows. Upstream does not supply these guarantees.
